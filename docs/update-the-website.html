How to update the website

Plain steps for putting the redesign live. Two ways to do it — pick whichever feels comfortable. Both end in the same place: a new version of the site, live in about a minute.

1. Before you start

You need two things:

  • The folder datasattva — the one with package.json inside it. This is your website project.
  • The zip file homepage-restructure-files.zip — this holds the ten files you're about to put live.
What's actually changing. The homepage has been cut down: a shorter challenge section, six advisory boxes instead of ten flat items, "Why DataSattva" in boxes, the graphic moved under the header, and one closing assessment section instead of two. The Insights section is retired — old links to /insights/ now say the page is gone, on purpose.

2. Method A — from your Terminal recommended

This is the reliable way: copy all ten files at once, check the site builds, then push. If anything is wrong, you'll see it before the world does.

Step 1 — open Terminal in the project folder

On Mac: open Terminal (press ⌘ + Space, type "Terminal", press Enter). Then drag the datasattva folder onto the Terminal window and press Enter — that takes you into the right place.

On Windows: open the datasattva folder, right-click on empty space, choose Open in Terminal (or "Git Bash Here").

Confirm you are in the right folder — this should print the project's name and its files:

ls

You should see package.json, src, build.mjs and a few others.

Step 2 — make sure your copy is up to date

git pull

This fetches anything changed since you last worked on it. If it says "Already up to date" — good.

Step 3 — save a copy of the current version (30 seconds, worth it)

git add -A
git commit -m "Checkpoint before homepage update"

If it says "nothing to commit, working tree clean", that's fine — there was nothing outstanding.

Step 4 — replace the ten files

  1. Unzip homepage-restructure-files.zip. You'll get a folder containing src, build.mjs, vercel.json and README.md.
  2. Open that folder and the datasattva folder side by side.
  3. Drag everything from inside the unzipped folder into the datasattva folder.
  4. When your computer asks, choose Replace / Merge — the new files should overwrite the old ones. Nothing gets deleted, only replaced.
Careful: drag the contents of the unzipped folder, not the folder itself. If you end up with a folder inside your project called homepage-restructure-files, the site won't pick up the changes — delete it and try again with the contents.

Step 5 — check it builds

npm install
npm run build

The first time, npm install takes a minute or two. Then you should see:

✓ Built 18 pages + 31 files in 40ms → dist/
If you see that line, you're good. If you see a red error instead, stop here — don't push. Send me the error text and I'll fix it.

Step 6 — look at it before anyone else does

npm run dev

Open http://localhost:8080 in your browser. Check the homepage top to bottom. When you're finished looking, go back to Terminal and press Ctrl + C to stop it.

Step 7 — send it live

git add -A
git commit -m "Homepage: trim content, boxes for services and why, one closing section"
git push

That's it. Vercel notices the push automatically and starts building. About 30–60 seconds later:

  1. Go to vercel.com/dashboard and open the datasattva project.
  2. Wait for the newest deployment to say Ready.
  3. Open www.datasattva.com and press Ctrl + Shift + R (Mac: ⌘ + Shift + R) to force a fresh load.

3. Method B — in the browser, no Terminal

Use this if you'd rather not touch Terminal. It's slower — one file at a time, ten times — but it needs nothing installed.

Step 1 — open your project on GitHub

Go to github.com, sign in, and open your datasattva repository.

Step 2 — for each of the ten files, do this

  1. In the file list, click into the folders to reach the file. For example, for the homepage: click src → pages → home.js.
  2. Click the pencil icon (top right of the file) to edit.
  3. Select everything in the editor — Ctrl + A (Mac: ⌘ + A) — and delete it.
  4. Open the same file from the unzipped folder in any text editor (TextEdit, Notepad — anything). Select all, copy.
  5. Paste it into the GitHub editor.
  6. Scroll to the bottom, click Commit changes.
  7. Leave the message as it is, or type Homepage update. Click Commit changes again to confirm.
Order doesn't matter, but finish all ten. If you stop halfway, the site will still build, but you'll get a half-styled page — new layout with old spacing, or the reverse. If you have to stop, finish the remaining files later the same day.

Step 3 — watch it go live

Each commit starts a new build. After the last one, open vercel.com/dashboard and wait for Ready, then check www.datasattva.com with a hard refresh.

4. Check your work before pushing

Ten things to look at on the homepage once it's live. Takes two minutes:

  • The graphic animates in under the header when the page loads
  • The headline wraps to two lines, and the orange button is visible without scrolling
  • The challenge section shows six numbered boxes, not a long list
  • Advisory services shows six white boxes in two rows of three
  • "View all ten advisory services" sits below them
  • "Why DataSattva" shows three boxes on the navy background
  • The page ends with the assessment section — "How ready is your organisation, really?" — and no "Next step" section after it
  • Insights is gone from the menu, and the menu has six items
  • Visiting www.datasattva.com/insights/ shows a "gone" message, not a broken page
  • On your phone: the menu opens, the boxes stack one per row, buttons are full width

5. If something goes wrong

The build fails on Vercel

Open the failed deployment in Vercel and look at the red text. The most common cause is a file that didn't get replaced properly. Simplest fix: redo Method A, Steps 4–7, being careful to drag the folder contents this time.

The site looks wrong, and you want yesterday's version back

Nothing is lost — every past version is kept.

  1. Go to vercel.com/dashboard → your project → Deployments.
  2. Find the deployment from before your change (check the date and time).
  3. Click the ⋯ menu on its right and choose Promote to Production.
  4. Confirm. The old version is live again in under a minute.

The new styling doesn't show up

Your browser is holding an old copy of the stylesheet. Press Ctrl + Shift + R (Mac: ⌘ + Shift + R). If you're on a phone, close the tab and reopen it. This is by far the most common "it didn't work" — and the site is usually fine.

You pushed by accident

Use the rollback in the section above. Don't try to rewrite history — promoting an earlier deployment is faster and safer.

6. Common questions

Do I have to do anything in Namecheap?

No. Your domain and DNS stay exactly as they are, and email keeps working. Only the website content changes.

Will this affect my Zoho email?

No. Nothing in this update touches mail settings.

Can I change the wording myself afterwards?

Yes — the homepage sentences live in src/pages/home.js, the service one-liners in src/data/services.js, and the menu and buttons in src/data/site.js. Edit, build, push, same as above.

What if I only want to change one thing later?

Then you don't need the zip at all. Edit that one file, run npm run build to confirm it's fine, then git add -A && git commit -m "your note" && git push.

Short version, if you only remember one thing: replace the ten files → npm run build → git add -A && git commit -m "Homepage update" && git push → wait for Vercel to say Ready → hard refresh the site.

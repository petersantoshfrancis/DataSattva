What to upload to GitHub

The exact file list for this website, what each folder does, and the one folder you should not commit. Everything below is already prepared in github-upload/ — or grab github-upload.zip and unzip it into your repository.

The short answer You do not have a hand-written index.html to upload. This site is generated: build.mjs assembles index.html and every other page from the files in src/ each time Vercel builds. So you upload the source (66 files, ~19 MB, mostly the preview screenshots), and Vercel runs npm run vercel-build to produce dist/ — which is exactly what vercel.json tells it to do.

Six top-level files, four folders, plus the preview screenshots. Nothing else is needed.

2 · Do not upload these

PathWhy notWhat happens
node_modules/68 MB of installed packages; npm ci rebuilds it from the lockfileAlready in .gitignore. Committing it makes the repo huge and Vercel's build slower.
dist/Generated output — Vercel creates it during the buildAlready ignored. If you commit it you get confusing stale pages whenever the build output differs from the checked-in copy.
data/Local enquiry log (enquiries.ndjson) — real people's detailsIgnored, and it should stay that way: never push personal data to GitHub.
.envReal secrets — the ZeptoMail token lives here locallyIgnored. Secrets go in Vercel → Settings → Environment Variables, never in the repo.
Don't copy the whole project folder by accident If you drag the folder into GitHub's web uploader, it will offer to include node_modules and dist. Select only the items in the tree above — or unzip github-upload.zip, which already excludes them.

3 · Two ways to get it in

Way A — drag and drop in the browser (no tools)

  1. Create an empty repository GitHub → + (top right) → New repository → name it datasattva-website → Private → do not tick "Add a README" → Create.
  2. Upload On the empty repo page click uploading an existing file. Unzip github-upload.zip on your computer (it unpacks to a single folder also called github-upload), then drag the contents of that folder — not the folder itself — into the browser. Wait for all 66 files to list, then Commit changes.

    Note The browser uploader silently skips empty folders and files starting with a dot, so afterwards check that .gitignore, .gitattributes and .env.example are present. If they're missing, add them with Add file → Create new file and the exact same name.

  3. Connect it to Vercel Vercel → Add New… → Project → Import Git Repository → pick the repo → leave all settings alone → Deploy.

Way B — command line (cleaner, keeps history)

cd /path/to/github-upload
git init
git add -A
git commit -m "DataSattva website"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/datasattva-website.git
git push -u origin main

To check what you are about to push before you push it: git status --short and git ls-files | wc -l — it should say 66, and should not contain node_modules, dist or data anywhere.

4 · What Vercel must be set to

You normally don't need to touch this — vercel.json is committed and wins. But if the project settings screen asks, this is the correct configuration:

SettingValue
Framework presetOther (no framework)
Build commandnpm run vercel-build
Output directorydist
Install commandleave default (npm ci / npm install)
Node version20.x or newer (the code uses modern ESM and fetch)
Root directoryrepository root — unless you committed the folder inside a folder, in which case point it at that folder
If the build fails with "No delivery channel" That is deliberate. tools/vercel-build.mjs refuses to produce a site whose forms would silently lose enquiries. Add ZEPTOMAIL_SEND_TOKEN and ENQUIRY_TO_EMAIL in Vercel → Settings → Environment Variables, then redeploy. Full walkthrough: docs/zoho-mail-and-live-site-guide.html, Part 3.

5 · After the first deploy

  • Open the .vercel.app URL and click through the menu — that is your proof the build is good before any domain moves.
  • Then follow Part 1, Step 1.2 of docs/zoho-mail-and-live-site-guide.html to point www.datasattva.com at this project.
  • Editing later: pages and copy live in src/pages/ and src/data/ — change a file, commit, Vercel rebuilds automatically. You never edit dist/ by hand.

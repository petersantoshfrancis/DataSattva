2 · How this build is structured

It is important to understand one thing, because it determines how you edit it later:

This is a static site generator, not a CMS and not a WordPress-style app. Running npm run build reads the content files in src/data/ and writes plain HTML into dist/. Vercel publishes dist/ and runs one serverless function for the contact form. There is no database to maintain and no plugins to update.

3 · Deploy to Vercel — step by step

3.1 Put the code in Git

Vercel deploys from a Git repository (or from the CLI — both are covered). Choose one.

Option A — GitHub (recommended; gives you web-based editing later)

  1. Create a private repository on GitHub called datasattva-website. Private is fine; Vercel can read private repos.
  2. Push the folder from your machine, inside ds/: 
    git init
git add .
git commit -m "DataSattva website — initial build"
git branch -M main
git remote add origin https://github.com/<your-org>/datasattva-website.git
git push -u origin main
    .gitignore already excludes node_modules, dist, data and .env, so no secrets or build output are committed.
  3. Confirm .env was not pushed. Open the repo on GitHub and check that no .env file is listed. Only .env.example should be there.

Option B — no Git at all

Install the CLI and deploy straight from the folder. You lose the web-editing workflow and the deploy history is harder to audit, but it works:

npm i -g vercel
cd ds
vercel login
vercel --prod

3.2 Create the Vercel project

  1. Sign in to Vercel and click Add New → Project.
  2. Import the repository you just pushed. If it is not listed, click Adjust GitHub App Permissions and grant access.
  3. Leave the framework preset as “Other”. vercel.json already supplies the build settings:
    Build commandnpm run vercel-build
    Output directorydist
    Install commandnpm install (default)
    Node version18.x or 20.x — either is fine
  4. Do not click Deploy yet. Add the environment variables first (next step), otherwise the production build will deliberately fail and tell you what is missing.

3.3 Add environment variables

In the import screen (or later under Settings → Environment Variables), add these. Set the scope to Production and Preview for all of them.

Why the build blocks itself npm run vercel-build refuses to produce a Production build if SITE_URL is missing or DS_CONTACT_EMAIL is still a .example address. This is on purpose: it stops a placeholder ever appearing on the live site. Preview and local builds are unaffected.

3.4 First deploy

  1. Click Deploy. The build takes roughly 30–60 seconds.
  2. Open the generated URL (datasattva-website.vercel.app or similar). Everything except the domain is now testable.
  3. Run this verification list before touching the domain:
    CheckExpected

    /services/third-party-privacy-risk-management/A deep page — confirms nested routes work
    /readiness-assessment/ → answer 12 questionsScore ring animates; download produces a .txt summary
    /contact/ → submit emptyField-level errors, no page reload
    /contact/ → submit validGreen success panel with a DS-YYYY-XXXXXXXX reference
    /sitemap.xmlLists ~26 URLs with your domain
    /robots.txtPoints at your sitemap

    Resize the window narrowNav collapses to Menu below ~1180 px
  4. Check Vercel → Deployments → your deployment → Functions → Logs after submitting the test form. You should see an enquiry log line with the reference. If email is configured you will also see emailSent:true.
Deploy is now repeatable Every future git push to main triggers a new Production deploy; pushes to other branches produce Preview URLs you can review before merging.

4 · Replace the existing live site

Two scenarios. Pick the one that matches where the current site is hosted.

Scenario A — the current site is also on Vercel

This is the cleanest case. The domain is already attached to a Vercel project; you are swapping which project serves it.

  1. Note the current setup first. In the old project: Settings → Domains (write down the exact domain and whether it is www, apex or both) and Settings → Environment Variables (copy anything the old site depends on for its own reasons — not needed by the new site, but keep the record).
  2. Add the domain to the new project. (Because the domain is already attached to a Vercel project, Vercel will offer to move it — accept. No Namecheap change is needed. See docs/zoho-mail-and-live-site-guide.html for the plain-language version.) New project → Settings → Domains → Add → enter www.datasattva.com (and datasattva.com if both are used).
  3. Vercel will warn that the domain is in use by another project. It offers to move it — accept. This is instantaneous and does not require DNS changes.
  4. If Vercel asks about DNS records, leave them alone; they are already correct because the domain was already on Vercel.
  5. Set the primary domain. In Settings → Domains, pick either www or the apex as primary and let Vercel redirect the other. Whatever you choose must match your SITE_URL variable — update it and redeploy if they differ.
  6. Verify using the checklist in 4.3.
  7. Keep the old project for two weeks. Do not delete it — it is your instant rollback. Its previous deployment is a one-click restore.

Scenario B — the current site is hosted elsewhere (shared hosting, Wix, WordPress, GoDaddy, an agency server)

  1. Attach the domain to the new Vercel project as above (Settings → Domains → Add). Vercel will show the DNS records it needs. Typical values:
    RecordHostValue
    A@76.76.21.21
    CNAMEwwwcname.vercel-dns.com
    Always use the exact values Vercel displays — they are per-project and can change.
  2. Lower the TTL on your existing records to 300 seconds (5 minutes) about an hour before you switch. This makes a rollback fast if something goes wrong.
  3. Before changing DNS, take a backup of the old site. Download the files (FTP/cPanel) or export the WordPress/Wix content. Record any URLs that currently rank in Google — you may want redirects.
  4. Update the DNS records at your registrar — replace the old A/CNAME values with Vercel's. Do this at a low-traffic time.
  5. Wait for propagation. Usually 5–60 minutes; up to 24 hours in worst cases. Vercel shows Valid Configuration when it sees the new records.
  6. SSL is automatic. Vercel issues a Let's Encrypt certificate once DNS resolves. Nothing to buy or install.
  7. Point the old URLs at the new ones. If the previous site had pages with different addresses, add redirects to vercel.json so existing links and search results do not break — for example: 
    "redirects": [
  { "source": "/about-us", "destination": "/about/", "permanent": true },
  { "source": "/privacy-policy", "destination": "/privacy/", "permanent": true }
]
    Add them, commit, and Vercel redeploys. Redirects already included cover /home, /about, /services, /contact, /insights, /assessment and /dpdp without the trailing slash.
  8. Keep the old hosting paid and reachable for 30 days. Do not cancel it or delete files on day one.
Do not skip this Do not change nameservers unless you intend to move DNS management to Vercel entirely. Changing only the A and CNAME records is enough, keeps your current email (MX) records intact, and is far easier to undo. If you do move nameservers, copy every existing MX, TXT and SPF record across first — otherwise email to @datasattva.com will stop working.

4.3 Verification after cutover

  • https://www.datasattva.com and https://datasattva.com both load the new site, one redirecting to the other.
  • The padlock shows a valid certificate (issued to your domain, not to *.vercel.app).
  • View source → the <link rel="canonical"> shows your real domain, not .vercel.app or .example. If it does not, SITE_URL is wrong — fix it, redeploy.
  • https://www.datasattva.com/sitemap.xml shows your domain in every <loc>.
  • Submit a test enquiry and confirm it arrives (see section 8).
  • Open the site on a phone, not just a narrow window.
  • Check email to your own domain still arrives — proof the MX records were untouched.

4.4 Rollback, if needed

  • Vercel-only issue: Deployments → pick the previous working deployment → ⋯ → Promote to Production. Live in seconds.
  • Domain issue: restore the old DNS values at your registrar (that is why you lowered the TTL) or move the domain back to the old Vercel project.

5.1 Worked example — publishing a new article

Open src/data/insights.js, find the insights array, and append an object like this before the closing ];:

{
  slug: 'dpdp-consent-notice-checklist',      // becomes /insights/dpdp-consent-notice-checklist/
  title: 'A consent and notice checklist before May 2027',
  category: 'consent-management',             // must match a slug in insightCategories
  draft: false,                               // false removes the "Draft content" badge
  author: 'Ananya Rao',
  date: '2026-11-20',                         // ISO date
  readingTime: '6 min read',
  excerpt: 'Six checks that catch most notice and consent problems before they become findings.',
  lede: 'One opening paragraph, shown larger at the top of the article.',
  blocks: [
    { type: 'h2', text: 'Start at the collection point' },
    { type: 'p', text: 'Body paragraph. Simple HTML entities work (&mdash; etc.).' },
    { type: 'ul', items: ['First point', 'Second point'] },
    { type: 'callout', title: 'Field-tested check', text: 'A highlighted aside.' },
    { type: 'quote', text: 'An optional pull quote.' },
  ],
},

Commit. The article page, its card on /insights/, its category listing, the three homepage article cards and the sitemap entry all appear automatically.

5.2 Worked example — changing an assessment question

In src/data/assessment.js, each question looks like this:

{
  id: 'q5',
  area: 'Consent',
  weight: 3,                       // 1–3; 3 = foundational
  question: 'How is consent captured, recorded and withdrawn across your digital channels?',
  why: 'Shown under the question and reused as the finding text in the results.',
  service: 'consent-and-privacy-notice-frameworks',   // which service the finding links to
  options: [
    { label: 'Consent is bundled into terms or pre-ticked', score: 0 },
    …
  ],
}
  • Wording changes are safe. Do not change id values for existing questions — the option weighting and the results logic key off them.
  • Higher weight = more influence on the score and a higher chance of a Critical gap rating.
  • If you add a question, update the "0 of 12 answered" label and the "12 questions" wording — search for of 12 in src/pages/assessment.js and src/pages/assessment-embed.js.

6 · Three editing workflows

A · GitHub in the browser Easiest

Open the repo on GitHub, press . (full stop) on your keyboard — it opens a full VS Code in the browser. Edit the file, commit to main, and Vercel deploys automatically in about a minute. No installation, works on any machine, nothing to update.

Best for: copy edits, new articles, contact details, service wording.

B · Local development Most control

Clone the repo, then:

npm install
npm run dev      # preview at localhost:8080, rebuilds on save
npm run build    # regenerate dist/
git push

Best for: layout changes, adding pages, design work. Requires Node 18+.

C · A headless CMS, if non-technical editors will maintain it If several people need to publish without touching code, the content files can be swapped for a CMS (Sanity, Contentful, Storyblok) — the data shapes in src/data/ are already clean objects, so the change is contained to the build script. This is a project in itself; ask if you want a scope and estimate.

Before every push, run these two checks locally (30 seconds)

npm run build          # regenerate the site
npm run check:links    # broken links, duplicate titles, missing meta, sitemap

8 · Making the contact form deliver email

Both the contact form and the optional "send my assessment result" form post to api/enquiries.js, which validates, checks a honeypot, applies a best-effort throttle, and then hands the record to src/lib/email.js. Nothing is stored on Vercel (no persistent disk), so a delivery channel is mandatory — the production build refuses to run without one.

This domain uses Zoho Mail The plain-language walkthrough for the actual stack (Vercel + Namecheap + Zoho) is docs/zoho-mail-and-live-site-guide.html. Read that one if you are the person clicking the buttons; this section is the technical reference behind it.

ZeptoMail — the Zoho route (recommended here, about 25 minutes)

  1. Create a ZeptoMail account at zoho.com/zeptomail, signing in with the same Zoho account as Zoho Mail. Pick the same data-centre region as your mailbox (India → api.zeptomail.in). Free tier: 10,000 emails, far more than a brochure site needs.
  2. Add a Mail Agent → add and verify the sending domain. ZeptoMail shows a TXT, a CNAME and usually a DKIM TXT. Add them at Namecheap → Advanced DNS (do not move nameservers). If an SPF record already exists for Zoho Mail, edit it to include ZeptoMail rather than adding a second one — two SPF records invalidate each other.
  3. Create a Send Mail Token (Mail Agent → SMTP/API → Create Send Mail Token). It is displayed once; store it in a password manager.
  4. Vercel → Settings → Environment Variables (tick Production, Preview and Development): 
    ZEPTOMAIL_SEND_TOKEN    = (the send mail token)
ZEPTOMAIL_API_HOST      = api.zeptomail.in      # .eu / api.zeptomail.com for other DCs
ENQUIRY_TO_EMAIL        = hello@datasattva.com
ENQUIRY_FROM_EMAIL      = DataSattva Website <website@datasattva.com>
SITE_URL                = https://www.datasattva.com
# optional:
ZEPTOMAIL_BOUNCE_ADDRESS = bounce@datasattva.com
    ENQUIRY_FROM_EMAIL must be on the verified domain. The address does not need to be a readable mailbox.
  5. Redeploy. Deployments → ⋯ → Redeploy. Environment variable changes only take effect on a new deployment.
  6. Submit a test enquiry. The email arrives at ENQUIRY_TO_EMAIL with the enquirer's address as Reply-To. Vercel function logs show enquiry-sent with the provider, or enquiry-undelivered with the full record and the reason.

Other channels

  • Resend: same shape — RESEND_API_KEY + ENQUIRY_TO_EMAIL + ENQUIRY_FROM_EMAIL. Only used when ZEPTOMAIL_SEND_TOKEN is absent.
  • SMTP: SMTP_HOST / SMTP_USER / SMTP_PASS (port 465 = TLS, 587 = STARTTLS). Intended for self-hosted deployments running server.mjs. Do not use it on Vercel: SMTP sends can be silently dropped when the function returns, which is exactly why ZeptoMail's HTTP API is used there. Zoho Mail SMTP works fine on a VPS or Render/Railway.
  • Webhook into a CRM or Slack: ENQUIRY_WEBHOOK_URL (and ENQUIRY_WEBHOOK_TOKEN if required). Combines with any of the above.
Failure behaviour — deliberately honest If every configured channel fails, the endpoint logs the complete record (nothing is stored anywhere on Vercel, so the log is the only copy) and returns HTTP 503 with a message asking the visitor to email directly, quoting their reference. It never shows "thank you" for an enquiry that was not delivered.

Alternatives

  • Webhook into a CRM or Slack: set ENQUIRY_WEBHOOK_URL (and ENQUIRY_WEBHOOK_TOKEN if required). The full enquiry is POSTed as JSON — Zapier, Make, HubSpot, Salesforce and Slack incoming webhooks all work.
  • Both: set both and you get an email and a CRM record.
  • Where do submissions go on Vercel? Nowhere durably — there is no persistent disk. If you need an archive, use the webhook (to a sheet/database) or add a KV store. The site's privacy notice currently says enquiry records are retained 24 months; keep that statement accurate to whatever you actually build.
Spam and rate limits The endpoint has a honeypot field and a best-effort per-instance throttle (8 per 15 minutes). Serverless instances are ephemeral, so this is not a hard limit. If you see spam, enable Vercel Firewall (Project → Firewall → rate limit rule on /api/enquiries), or add Cloudflare Turnstile to the form.

9 · Post-launch checklist

  • ☐ Domain resolves, certificate valid, canonical shows the real domain.
  • ☐ Test enquiry received by email, with the reference number.
  • ☐ Google Search Console: add the domain property, submit sitemap.xml.
  • ☐ Bing Webmaster Tools: submit the sitemap.
  • ☐ Old URLs that still receive traffic are redirected in vercel.json.
  • ☐ Privacy notice and terms reviewed by counsel; legal entity, DPO and jurisdiction filled in.
  • ☐ Decision recorded on analytics, and the privacy notice updated if anything is added.
  • ☐ Tested on a real iPhone and a real Android device, not just a narrow browser window.
  • ☐ Someone is named as owner of the enquiry inbox, with a response target (the site promises two business days).
  • ☐ Diary reminder to re-verify the regulatory content when MeitY notifies any change to commencement dates — and to update regulatoryStatus.verifiedOn.
  • ☐ Old hosting kept alive for 30 days, then cancelled.

11 · Appendix — hosting somewhere other than Vercel

The site is portable; only the contact endpoint is Vercel-specific.

Static host + serverless function

Netlify, Cloudflare Pages, Azure Static Web Apps and AWS Amplify all work: publish dist/, and port api/enquiries.js to that platform's function format (the validation logic in src/lib/enquiry.js is framework-agnostic and reused as-is).

Your own Node server

npm ci && npm run build && node server.mjs serves the site and the contact endpoint from one process, writing enquiries to data/enquiries.ndjson. Requires a host that keeps a process alive — a VPS, Render, Railway or Fly.io — not a static host.

Portable extras dist/assessment-embed.html is a single self-contained file (no external CSS, JS or fonts) that can be embedded on any site with an iframe, or emailed to a client. It runs the same twelve questions and the same scoring model.
